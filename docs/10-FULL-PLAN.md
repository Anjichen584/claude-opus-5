## 1. 完整版是什么(v1.0 规格书)

**一句话**:三个章节各自有"自己的怪、自己的地形、自己的 Boss、自己的套路",从营地到无尽连续可玩;
界面与手感打磨到"不用解释就能玩";中文 + 英文;可在桌面与手机浏览器游玩,并发布到 itch.io 与 Pages。

**判定标准**:下面这张表全部打勾 = 完整版。它是**可数**的 —— 每一项都能在仓库里 grep 出来。

| 维度 | 现状(2026-09-29) | **v1.0 目标** | 差额 |
|---|---|---|---|

## 2. 发行形态:三条路,成本差 3 倍(需要拍板)

| 方案 | 做法 | 增量成本 | 建议 |
|---|---|---|---|
| **A. 网页 + itch.io** | 现有 web 构建 → Pages(已有)+ itch 上传 zip | **≈2 轮** | ✅ 推荐主线 |
| **B. A + 桌面包装** | 用 Tauri/Electron 包一层 → Steam/itch 桌面版 | **+4 – 6 轮**(打点、签名、自动更新) | ✅ 想上 Steam 就走这条 |
| **C. Unity 原生** | 在 Unity 里重做渲染/UI/场景/出包(逻辑层已有) | **+25 – 35 轮**,等于把游戏再做一遍 | ❌ 不推荐(除非 Steam 是硬需求) |

**结论**:发行目标是 **A**,想要"看起来更像主机游戏"再考虑 B。Unity 副线在完整版里的定位是
**"代码与数据的第二实现 + 学习/移植价值"**,不是发行载体 —— 这条要说清楚,否则会在 D4 那一步吞掉一个月。

## 3. 四个里程碑(每段都有可检查的验收门)

### M1 · Alpha｜可玩 Demo(轮 1–10)
> 目标:把链接发给朋友,他能自己玩 20 分钟不卡壳。

**验收门**
- ☐ 1 名真人试玩(非作者),记录"卡壳点 ≤3 处",当场修完
- ☐ 三章各有一次通关录像/截图;HUD/背包/菜单里**不再出现程序化占位方块**
- ☐ 四职业手感可区分(同一段木桩,四职业 DPS 曲线与操作感不同)
- ☐ 触屏能完成一次完整推图(取决于 §9 决策①)
- ☐ web 单测 ≥ 250 · C# ≥ 450 · CI 双绿 · itch 私有页可下载
- **可展示物**:战斗 GIF ×1、技能连招 GIF ×1、Boss 战 GIF ×1

### M2 · Beta｜内容完整(轮 11–30)
> 目标:规格书 §1 的内容栏全部打勾,只剩打磨。

**验收门**
- ☐ 27 怪 + 3 中 Boss + 3 章 Boss 全部进图鉴;18 模板每章 6 个
- ☐ 词条 24 / 传奇 9 / 蓝图 6 可用 / 药剂 4 种
- ☐ 难度 4 层 + 无尽模式;"普通难度通关 ≥1 次"是深渊 I 的解锁条件(有门槛但不劝退)
- ☐ **5 名外部试玩者**各 30 分钟;前 15 分钟留存(愿意开第二局)≥3/5
- ☐ web 单测 ≥ 380 · C# ≥ 600
- **可展示物**:三章地貌对比图、中 Boss 三连剪影、难度选择界面

### M3 · RC｜打磨(轮 31–44)
> 目标:功能冻结,只修不打;跨过这条线就准备卖。

**验收门**
- ☐ 动画 78 组全量接入;VFX 30 张;三场 Boss 演出
- ☐ EN 文案 100% 覆盖 + 一次母语校对(或高质量审校),无截断/错位
- ☐ 性能:首屏 < 2s(普通宽带)、战斗中 60fps(中端笔记本)、构建产物 < 6 MB(gzip)
- ☐ 存档:v1→v3 迁移矩阵全绿 + 导入/导出存档码可用
- ☐ QA:三章各连打 5 遍,零阻断 bug;控制台零 error
- ☐ web 单测 ≥ 450 · C# ≥ 700 · 功能冻结 tag
- **可展示物**:宣传用 30s 预告草稿、EN/中文同屏对比

### M4 · 发行(轮 45–52)
> 目标:v1.0 上线,并且"出事能回滚"。

**验收门**
- ☐ 商店页:截图 8 张 / GIF 6 条 / 预告 30s / 中英双语说明
- ☐ 发布流水线:`git tag v1.0` → 自动构建 → itch + Pages 产物归档(一条命令回滚上一版)
- ☐ 版权清单:每张 sprite 的来源与生成方式、字体与音频许可、AI 生成声明、MIT 与商用条款说明
- ☐ 上线清单:反馈渠道(issue 模板)、FAQ、崩溃上报开关(默认关)
- ☐ 上线 + 热修预案(24h 内可发补丁)
- **可展示物**:正式商店页 + 发布公告

## 5. 双线节奏(Unity 阶梯)

**原则**:web 是发行载体(每轮必动);Unity 是镜像与第二实现(每 3–4 轮动一次,且始终"逻辑可测"优先)。

| Unity 阶段 | 内容 | 落在哪几轮 | 人工依赖 |
|---|---|---|---|
| U1 逻辑跟随 | 新怪/新地形/难度/无尽的 C# 镜像 + parity | 2, 4, 5, 11–17, 23, 24, 36, 42 | 无 |
| U2 面板 UI | 图鉴 / 成就 / 排行榜 / 难度选择 | M2 内穿插(可与 web 轮并行) | 无(逻辑已就绪) |
| U3 系统镜像 | 商店 / 装备穿戴 / 挑战乘区 / 存档落盘 | M2–M3 | 无 |
| U4 渲染接入 | 地形表现、动画序列、VFX、像素图导入 | M3 | 需 Sprite 导入器(Editor) |
| U5 场景工程 | 真场景、UI Canvas、出包配置 | **M3 之后** | **必须人工**(Editor GUI) |
| U6 可选出包 | 桌面/移动包(仅决策②=C 时才做) | 发行后 | 人工 + 商店流程 |

> **纪律**:每轮在 06-STATUS 里写明"哪条线动了什么";连续两轮只动 web 是允许的(发行优先),
> 但**连续两轮完全不动 web 不允许**(它会拖死交付)。
